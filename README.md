# AI Native 工作台（包名 dsh-requirement-dev-workbench）

DSH Desktop 工作台：把**「拿任务 → 开发 → 验收」串成一条流水线**——跨多张飞书多维表格看开发任务与进度，拉取**飞书文档**信息，用**专家/专家团**跑完整流程（**需求分析 → 代码开发 → 代码评审 → QA 测试**），选中本地项目后生成可以直接交给 AI 的开发指令，并能随手翻项目/全局 skill 与开发规范。模块可扩展。

从 **v4.2.0** 起，「验收」不再是点一下按钮：每个阶段的完成都要有**凭据**（命令 / 文件 / 测试 / 链接 / spec 路径）。没凭据也能完成，但会记成「已完成 · 无凭据」并在台账里单独计数。

> 包名 `dsh-requirement-dev-workbench` 与仓库身份沿用 v3（同一个工作台继续迭代，不新增第二个入口）；从 v4.0.0 起界面名称改为 **AI Native 工作台**，v4.1.0 起**记录详情从弹窗改成右侧分栏**（可收起、可拖拽调宽）。
>
> **每个版本改了什么，看 [CHANGELOG.md](./CHANGELOG.md)** —— 一条一句话，只讲用户能感知的变化。

- 形态：**自定义整块框架**（`customFrame: true`，对齐本机 SEO/GEO 工作台的布局方式）：顶栏 + 左侧模块导航 + 右侧内容区；右侧可展开宿主**原生对话**，一边看任务一边对着 AI 说。
- 模块：`总览`、`AI 全流程`、`飞书文档`、`项目开发`、`专家与专家团`、每张飞书表一个模块（默认 `开发需求 · <项目>`、`开发任务 · <项目>`）、`技能与规范`，模块栏底部有 `＋ 添加模块`、版本号与 `收起工作台`。
- 看板卡片：**固定长宽**（216×152），**卡片上展示哪些字段可在页面配置里勾选**（最多 4 个，一行一个「字段名 值」、超出省略、悬停看全文；不配就自动用 状态/负责人/优先级/期望完成时间），点卡片在**右侧打开详情栏**（可一键收起、可拖拽调宽，见下面「记录详情栏」）；卡片右上角是**执行记录角标**——已交付／进行中／已完成／受阻 + 次数，点进去就是这条需求的执行记录与状态按钮。
- 读数据的两条通道：优先用 lark-cli 的 ndjson（每条记录自带字段名）；只有拿不到时才退回值矩阵，并用返回体自带的 `data.fields` 对齐列名（**列名对不上就不显示数据并给出原因，绝不猜**）。写回状态走 `+record-batch-update`（记录的 `record_id`，`--json` 用 `@文件` 传，避开命令行引号问题），**点按钮后先在页面上确认一次才真的写飞书**。
- 数据：设置写在 DSH 数据目录 `requirement-dev-workbench/settings.json`，页面配置写在同目录 `view.json`，表结构缓存在 `fields-<tableId>.json`，执行记录写在 `runs.jsonl`；**不保存任何飞书凭证**，一律调用本机已登录的 `lark-cli`。

### 记录详情栏（v4.1.0；v4.1.2 收起改版，v4.1.6 列表默认铺满）

以前点一条记录是**弹窗**盖在内容上；现在改成**内容区右侧的分栏**，可以一边看列表一边看详情：

- **未选中记录时清单铺满内容区（v4.1.6）**：没有打开记录详情时，汇总清单列表自动占满可用宽度；选中一条记录后，再为右侧详情栏留出空间。
- **拖宽（并排布局下任何窗口宽度都能拖）**：列表与详情之间有一条**常显的细线**（悬停/拖动变品牌色），左右拖动改宽度；双击恢复 420px；聚焦后按**左右方向键**微调 24px。拖拽命中区加宽到 16px，不必精准点细线；
- **汇总清单详情尺寸保护（v4.1.5）**：详情栏限制在分栏容器内，列表不会被挤没；拖动开始时现场测量容器宽高，尺寸观察尚未更新时也不会用过期的默认范围；
- **并排是默认，不再跟着窗口宽度自动上下排（v4.1.4 修）**：v4.1.3 及更早版本里，工作台窄于 430px 会**自动**把列表与详情改成上下排，这时详情是**占满整宽**的——于是「拖宽度」在最需要它的窄窗口里反而完全没用。现在并排恒为默认，窄窗口照样有竖线可拖；
- **要上下排自己点（v4.1.4）**：详情栏顶部有「**上下排**」按钮，点了才改上下排（列表在上、详情在下，竖线换横线拖高度），再点「**并排**」回来；这个选择也存进 `view.json`；
- **拖到最窄不再跳到最宽（v4.1.4 修）**：拖动算出来的值恰好是 `0` 时，以前会被当成「没配过 → 用默认 420px」，于是松手/继续拖会让详情**猛地弹回最宽**。现在拖动值先压到 ≥1 再夹取，拖到最窄就稳稳停在最窄；
- **上下排时拖高度**：默认 280px，双击复位，上下方向键微调；高度同样两头都夹在可调范围内；
- **不拖也能改**：详情栏顶部有 **`－ 420px ＋`**（每次 40px，直接写回配置）；上下排布局下自动换成 **`－ 高 280px ＋`**；
- **单独收起（v4.1.2）**：点详情栏顶部的「收起」→ **只收这一栏**，列表恢复整宽，**选中的记录不丢**；页头会出现「**展开详情 · &lt;标题&gt;**」，点一下原样展开；
- **「关闭」= 取消选中**：想连选中一起清掉就点它（Esc 同样取消选中）；
- **宽度/高度/排布都存在 `view.json` 的本表切片里**（`detailWidth` / `detailHeight` / `detailCollapsed` / `detailFull` / `detailStacked`），下次打开一致。

**自测怎么跑（v4.3.0 起）**：

1. `node test/smoke.mjs` —— 回归组件纯逻辑与服务端行为（395 条，含阶段凭据、「done 必然有凭据」的降级、老数据兼容、验收标准机械检查、spec 白名单、更新日志解析与版本一致性）；
2. `node test/browser/itest.mjs` —— 浏览器会用**真实 lib/client.js 代码 + 真实 CSS + 真实 PointerEvent**量像素，包含「汇总清单详情已保存宽度超过窄容器」时列表和拖拽条仍可见的回归用例。

排障还可以看**界面自检上报**：客户端会把详情栏的真实几何（内容区宽高、当前详情宽高、可调区间、拖拽次数、是否选中和拖拽条是否渲染）POST 到 `GET /api/requirement-dev-workbench/ui/metrics`，只存内存、不含凭证。

## AI 全流程（专家团流水线，v4.0.0 新增）

把一条开发任务交给一个**专家或专家团**，按四段推进：**需求分析 → 代码开发 → 代码评审 → QA 测试**。

1. 在 `AI 全流程` 里选**一条开发任务**（来自开发任务表，认不到表会明确说「先在设置里选项目目录」）+ **谁来跑**（下拉里是本机已有的专家与专家团，默认跟着工作台当前选中的那个）；
2. 点 **「开始全流程」**，生成一条流水线：四个阶段各自一行，状态是 `待开始 / 进行中 / 已完成 / 受阻`，整体完成度按「已完成阶段 / 4」算；
3. 每个阶段三个动作：
   - **「发进对话」**：把这一阶段的开工指令直接发进当前对话（agent 模式）开跑，发不出去就自动退回复制；
   - **「复制指令」**：复制自己贴给任意 AI；
   - **切状态 + 存备注**：点状态按钮改这一阶段的进展，备注随状态一起存（按事件追加写 `flows.jsonl`，历史可回溯）；
4. **受阻可重试**：阶段标成「受阻」后会出现「重试这一阶段」，把状态推回进行中并带上原因；
5. 阶段指令里写死了三件事：**只做这一段、必须给凭据（不是一句「已完成」）、没做完要明确说「未完成」并写清卡在哪** —— 避免 AI 一口气跑完却什么都没留证。指令里还会带上你选的**专家/专家团的角色设定与角色定义文件路径**，以及前面几个阶段的状态、备注与**凭据**（`规格` 类凭据连文件路径一起带）。

> 四段默认挂的是本机已有的四位专家角色（`DSH_HOME/agents/` 下的 `product-requirement-expert`、`fullstack-architect`、`code-review-expert`、`qa-test-expert`）；不装专家也能用，指令照样能复制给别的 AI。

### 阶段凭据（v4.2）

「已完成」不是凭据。这一版把每个阶段的完成变成一件**带据可查**的事：

- 每个阶段右侧有 **`贴凭据`**，以及 `凭据 N` / `无凭据` 角标；
- 凭据分五类：**命令**（跑过的命令 + 输出摘要）、**文件**（`git diff --stat` 那种改动清单）、**测试**（用例数 / 通过失败条数）、**链接**（PR / CI）、**规格**（项目里 skill 产出的 spec 文档路径）；
- **备注不算凭据**。「存备注」只是给人的话，不进凭据列表 —— 这条是刻意的：把 markdown 当证据就是自欺；
- 标「已完成」时如果该阶段一条凭据都没有：先弹一次确认，确认后状态记成 **`已完成 · 无凭据`**（不是 `done`）。**服务端还会兜底**——即使前端漏判，`done` 在没有凭据时一律降级成 `done_unverified`，所以「有凭据」这条不变式不会破；
- 顶部显示 `凭据 N 条 · 无凭据完成 M 个阶段`，这就是台账口径：**不拦你，但让人看得见哪几条是靠自觉完成的**；
- 上一阶段的凭据会带进下一阶段的指令，`规格` 类凭据连**文件路径**一起带 —— 下一阶段能直接去读那份 spec，不用人再贴一遍。

> 老数据不用管：`flows.jsonl` 只加字段不改结构，以前的事件没有 `evidence` 就当没贴凭据，流水线照常显示。

## 飞书文档（取文档信息，v4.0.0 新增）

- 在 `飞书文档` 里**贴一条文档链接**（`/docx/` 或 `/wiki/`，带 query 的链接也认），点「拉取文档」；
- 走本机已登录的 **`lark-cli docs +fetch --doc-format markdown`**，把正文拉成 Markdown 存在工作台数据目录（`docs.json` 记清单、`docs/<文档 id>.md` 存正文），**不保存任何飞书凭证**；
- 左边是已拉取清单（标题 / 字数 / 拉取时间），右边看正文，可**「复制正文」**或**「送进对话」**（送进对话时超过 8000 字会自动截断并注明是节选）；
- 读不到就**原样显示 lark-cli 的报错、错误码提示和实际执行的命令**，并且**不落盘、不塞进清单**——不假装成功。

## spec 文档（skill 产出，工作台只认不造）

spec 由项目里的**开发 skill 流程**生成（`dev-task-sync` 的 `.dev-tasks/`、OpenSpec 的 `openspec/changes/`、Spec Kit 的 `specs/` 等）。工作台**不自己再写一份**——那只会变成第二份要维护、还会漂移的文档。它做三件事：

1. **认出来**：扫项目里的 `specs/`、`openspec/specs/`、`openspec/changes/`、`.dev-tasks/`、`doc/specs/`、`docs/specs/`，加上根目录的 `*.spec.md` / `requirements.md` / `spec.md`（最多 120 份、单份 200KB 以内、最深 4 层）；
2. **当凭据用**：`贴凭据` 里选类型「规格」，下拉直接列扫描结果，选中即引用，路径存进凭据的 `ref`；
3. **检查验收标准能不能失败**：选中后立刻读正文，找 `验收标准 / Acceptance Criteria` 段落，对每条做三条机械检查——有没有**触发条件**（当…时 / 如果…）、有没有**可判定结果**（返回 / 拒绝 / 显示…）、是不是**太长**（> 60 字）。不合格的标黄并列出来，**不阻断**。

为什么只做机械检查：那套方法论公认的问题是文档太长没人看（Böckeler 的原话是「我宁可 review 代码，也不想 review 这堆 markdown」）。可判定的标准迟早会变成一条测试，散文不会。所以这里只挑「这句话能不能失败」，不给文采打分。

读 spec 走**白名单**：只允许读扫描结果里的文件，客户端传别的路径一律拒绝。

## 总览

- 每张表一块卡片：记录条数、按「状态/进度」字段的**进度条**（完成 / 进行 / 待办 / 百分比）、状态分桶、几条样例。
- 一张表读不到时，只把这张表的错误显示出来，不影响别的表。
- 下面是**工作台执行记录**（见下）。

## 表的模块：三种视图

| 视图 | 用途 |
| --- | --- |
| 汇总清单 | 一行一条记录、按配置的列展示字段内容；「复制清单」把当前筛选结果整段复制，直接贴给 AI 或存档 |
| 卡片看板 | 按「分组字段」自动分成若干模块，每个模块一组卡片（标题 + 编号/优先级/类型/负责人 + 摘要），卡片可在模块间拖拽 |
| 进度 | 选一个字段（状态 / 单测状态 / 联调状态…）看分桶占比与完成度，用来盯任务进度 |

**页面配置（筛选与分组）**：分组字段、**卡片上展示哪些字段**、卡片摘要字段、汇总清单显示哪些列、按表字段的筛选条件（选项字段多选、文本字段包含）、拖拽是否回写飞书。**配置按表分别保存**，存在 `view.json`，下次打开一致。

**拖拽**：卡片拖到别的模块 = 改这条记录的「分组字段」值（默认只改页面；勾了回写开关才写飞书，写之前同样会弹页面确认）；模块头部可拖动排序，可折叠/隐藏。

**回写飞书**：详情里点状态按钮、或拖卡片换模块（开了回写开关）都会先弹一个确认框，写明「哪条记录、哪个字段、改成什么」，点「确认写回飞书」才真的调 lark-cli；写失败会把 lark-cli 的原始报错和实际命令一并显示出来。

## 工作台自己的执行记录

每次点「生成开发指令并复制」，工作台就记一条：哪条需求/任务、哪张表、哪个项目、什么时候、什么备注。在总览或条目详情里可以把状态标成 `已交付 / 进行中 / 已完成 / 受阻`（事件追加写入，历史可查）。

**一个任务只留一条记录（v4.1.1 起）**：同一个任务再点「生成开发指令并复制」是**更新那一条**——刷新时间/项目/备注、次数 +1，**不会多出一条**；已经标好的状态不会被冲掉，历史照旧留全。判定归并的键是「表 + 记录 id」（没有记录 id 时退到标题），所以两张表里的同名记录不会串到一起。

- 界面上按「生成 N 次」显示次数（卡片角标 `×N`），不再是行数；
- **老数据不用管**：以前同一条任务被点出的多条记录，读出来时就已经合并成一条（`runs.jsonl` 文件本身不动，不删你的历史）。

## 项目开发（AI 开发任务进度）

左侧导航里与 `总览` 并列的内置模块，把**开发任务表**的状态和工作台自己的 **AI 执行记录**合成一张进度视图：

- **任务进度**：按任务表的状态字段分桶（待开发 / 开发中 / 已完成 …）+ 整体完成度进度条；
- **AI 开发进度**：已交付 / 进行中 / 已完成 / 受阻 / 还没交给 AI，各自多少条（来自 `runs.jsonl`，按记录 id 或标题归到每条任务）；
- **任务清单**：编号 / 标题 / 状态 / 模块或负责人 / AI 最新状态角标（带次数）/ 最近更新时间；**点一行 = 复制这条任务的开发指令**，直接贴给 AI；
- 任务表还没记录（或完全没有执行记录）时，直接列出「最近 AI 执行记录」，不会给一片空白。

| 项目 | 所选项目下的 `.dsh`、`.agents`、`.agent`、`.claude`、`.codex`、`.code`、`.cursor`、`.gemini`、`.github`、`.opencode`、`skills` 各自的 `/skills` |
| 自定义 | 主机配置 / 工作台设置里加的目录 |

- 筛选四层可叠加：**范围**（全部 / DeepSeek Harness / 全局 / 项目 / 自定义，带条数）→ **目录约定**（`.claude`、`.codex`…）→ **类型**（技能 / 角色规范 / 项目规范文档）→ **关键词**；
- 每个来源目录都会标出**是否命中**（✓ 有 / × 没有），没建的目录也列出来，方便知道还能往哪放；
- 除了 `<目录>/skills/<名>/SKILL.md`，`<目录>/agents/*.md` 这类**角色 / 规范文件**也会按 `kind=agent` 扫出来；再加上项目里的 `doc/standards/*.md`、`AGENTS.md`、`CLAUDE.md`；
- **来源分组可以收起/展开**：点分组标题（▸/▾）折叠那一组，右上角是「全部收起 / 全部展开」，找东西时不会被十几个目录刷屏；
- 点左边任一条 → 右边直接看正文（只读，不允许读工作台范围外的路径）。

**新建技能**（`＋ 新建技能`）：填名称（自动归一成 kebab-case）、一句话描述、使用场景、步骤、注意/红线，默认写进 **DeepSeek Harness 通用技能根**（`DSH_HOME/skills/<名>/SKILL.md`，任何项目都能用），也可以选「只放当前项目」（写进 `<项目>/.claude/skills`）。重名会拦住并提示，确认覆盖才重建；技能名里的路径字符会被去掉，写不出目录之外。

## 专家与专家团（在对话里选一个「人」来帮你）

参考本机 WorkBuddy 的模式：**专家 = 一份角色定义文件**，**专家团 = 一个团长带几名专家**。在这里选中谁，之后「生成开发指令」和「复制开场白」就会以谁的身份说话。

| 概念 | 落地成什么 | 放哪 |
| --- | --- | --- |
| 专家 | `agents/<标识>.md`：frontmatter（`name` / `description` / `displayName` / `profession` / `maxTurns`）+ 正文四段（核心能力 / 工作流程 / 输出规范 / 注意事项） | 通用：`DSH_HOME/agents/`；只放当前项目：`<项目>/.claude/agents/`（也可 .agents / .codex） |
| 专家团 | `experts/teams.json`：`{id, name, profession, description, lead, members, flow}` | 通用：`DSH_HOME/experts/teams.json`；只放当前项目：`<项目>/.dsh/experts/teams.json` |

- **专家库自动扫出来**：本项目 `.claude/agents`、`.agents/agents`、用户级 `~/.claude/agents`、`~/.codex/agents` 等位置里已有的角色文件都会列出来（同一个名字在多个目录各放一份时**只列一条**，其它位置标成「同名还在：…」，以当前项目那份为准，这样在对话里选人不会选岔）；
- **选中**：列表上方一排按钮（`专家 · 老陈`、`专家团 · HR 交付专家团`、`不用专家`），选中的那个会高亮并存进设置，下次打开还在；
- **选中之后发生什么**：详情里「生成开发指令并复制」的指令开头会多一句「请你以「老陈 · Java 后端开发专家」这个专家的身份来完成下面这条开发需求」，并附上**角色定义文件路径**让 AI 先读它；选专家团则改写成「按「XX 专家团」的分工」，列出团长、成员、每人角色定义文件和协作流程；
- **「复制开场白」**：详情里一键复制一句开场白（「请以 … 的身份帮我继续；角色定义：…」），粘贴到左侧对话即可以这个专家身份开工；
- **新建专家**：**推荐「交给 AI 完善并创建」**（见下节）——你只写一句话，剩下的由 AI 按专业流程补齐；想手写的人点「我自己填（高级）」仍然可以逐项填标识、显示名、职业定位、核心能力 / 工作流程 / 输出规范 / 红线（一行一条），选通用或只放当前项目，写出来就是标准的 `agents/<标识>.md`——Claude / Codex / DSH 这些工具自己也能读到；
- **新建专家团**：同样推荐「交给 AI 完善并创建」（一句话说清要什么样的团队，AI 补团长、成员分工与协作流程）；「我自己填（高级）」里可以点选成员、指定团长、写协作流程，成员不存在（还没建那位专家）会被拦住并点名。

### 创建专家 / 专家团：一句话，页面里直接建好（v3.8.0 起；v3.9.0 起默认在页面内完成）

「＋ 新建专家 / ＋ 新建专家团」点开后**不再先给你一张技术字段表**，而是一句话：

1. 你只写**「你想让这位专家干什么」**（一句话就够，比如「一个盯支付对账的后端专家」/「要一个从需求到测试一条龙的团队」），选「通用（所有项目可用）」还是「只放当前项目」；标识、显示名可以留空让 AI 取；
2. 点 **「AI 直接创建」** → **就在这个页面里完成**：工作台调宿主的 `llm` 服务，用内置的专业养成流程（**定位与边界 → 能力清单 → 工作流程 → 输出规范 → 红线与自检 → 触发场景**，专家团再加一步「团队编排：谁先动、谁拍板、谁验收」）把这句话补全成结构化草稿，然后**自己按标准格式落盘**——通用写到 `DSH_HOME/agents`，项目写到 `<项目>/.claude/agents`；专家团还会把缺的成员专家一并建好，条目写进 `experts/teams.json`；
3. **全程不经过右侧对话，也不需要你复制任何提示词**。页面上直接出结果卡：名字、落盘绝对路径、成员名单、用的模型，以及 AI 替你做的假设；旁边就是**「选它开工」**，选完这轮对话就交给它；
4. 指令里**明令 AI 不要反问你、不要要求确认**：描述里没写到的细节由它按专业判断补齐——这就是「内部有专业流程来丰富完善」，不需要你被字段审问。

退路（都还在，路不会断）：

- **「发到对话里做」**：宿主没提供「直接调模型」的能力时用这条——工作台把同一份养成指令**自动发进你当前这轮对话**（agent 模式），由对话里的 AI 落盘；这时你仍然不用复制提示词；
- **复制兜底**：连「替你发消息」也拿不到时，工作台把指令复制到剪贴板并贴在一个可手动复制的框里；
- **「我自己填（高级）」**：想逐项手写的人，原来的字段表一直都在。


### 对话输入框那排「＋ 专家」（v3.7.1 起；v3.7.2 起固定在最左端）

输入框工具栏最左边（宿主原生 `＋` 控件那一排）会多一个 **`＋ 专家`** 小按钮：

1. 点它 → 弹出「这轮对话交给谁？」→ 选一位专家 / 一个专家团（当前选中的会勾出来，按钮上也会显示是谁）；
2. 选完**开场白直接写进输入框**（宿主通过 slot 标准 props 提供 `inputActions.insertText`，是一次可撤销的插入，不会清掉你已写的内容），你接着补一句需求就能开工；
3. 万一编辑器拒收（或宿主没给这个能力），工作台**自动退回复制到剪贴板**并提示你粘贴，结果不会丢；
4. 选人同时会记进工作台设置，所以详情里「生成开发指令」带的也是同一个角色。

> 这里的专家/专家团是给**在 DeepSeek Harness 上干活**用的：选一个专家 = 把这轮对话交给这个角色来理解需求、拆任务、写实现；它跟代码里的 subagent / AgentTeams 无关，不需要在那里注册。
> 宿主没有开放 slot 时（老版本 Desktop），这个按钮自动消失，工作台其余部分照常可用。

## 怎么用

1. 打开工作台 → 先看 `总览`：项目里已有的表会被自动认出（`.requirement-sources.json`、`.dev-task-sources.json`），不需要重填表格地址。
2. 进某张表的模块 → 用「汇总清单 / 卡片看板 / 进度」看这一轮要做什么、做到哪了。
3. 点一条记录 → 详情（原始需求 / 详细设计 / 验收标准分块展示）→ 「生成开发指令并复制」。
4. 需要文档上下文时去 `飞书文档`：贴链接拉正文，拉到后可以「送进对话」让 AI 直接读。
5. 想一条龙跑完就去 `AI 全流程`：选任务 + 选专家团 → 「开始全流程」→ 逐段「发进对话」或「复制指令」，每段标状态、存备注、受阻重试。
6. 把指令粘到左侧 AI 对话，AI 就在该项目里按已有规范/skill 做前后端开发。
7. 盯进度就去 `项目开发`：任务状态分桶 + 每条任务的 AI 执行状态。
8. 需要的话点「待开发/开发中/已完成」或直接用拖拽把状态回写飞书表格。
9. `技能与规范` 里按范围/目录筛选现有技能（分组可收起），缺规范就当场新建一个跨项目通用的。
10. 想指定「谁来帮你」就去 `专家与专家团`：选一个已有的、或者自己建一位专家/一个专家团，再回详情复制指令或开场白。

## 读表方式

- 优先 `lark-cli base +record-list --format ndjson`（带字段名），只读；同一张表 60 秒内复用内存缓存，`刷新` 会强制重读；
- **「表本来就是空的」和「读失败」是两件事（v4.2.0）**：读到 0 条显示「这张表当前 0 条需求（已成功读取，表内暂无记录）」，读失败才出红色错误块并带上 lark-cli 的原始报错与命令；任务表按 `kind` 说「任务」，不再复用「需求记录」字样；
- **日期字段统一显示成 `yyyy-MM-dd HH:mm:ss`（v4.2.1）**：飞书日期字段回的是 ISO 串（`2026-10-10T00:00:00.000+08:00`），列表、卡片看板、详情栏、开发指令里都按本地时间转成 `2026-10-10 00:00:00` 再显示；不是时间的普通文本（需求编号这类）原样不动。
- **认不出的表不再静默丢弃（v4.2.0）**：缺 `baseToken`、缺 `tableId`、或 `?table=` 写的是表名而不是 `tblxxxx` 时，总览顶部会列出「有 N 张表没被认出来」并给出原因与配置文件路径；
- ndjson 正常就按它显示：**表本来就是空的（0 条）不会被当成「通道坏了」**（v3.7.1 修正：会用值矩阵交叉确认一次，两边都是 0 条就安静显示空表）；
- ndjson 真的失败时才退回 `--format json` 的值矩阵，并用 `+field-list` 对齐列名，列数不一致就不猜、直接报错；
- 表结构用 `lark-cli base +field-list` 读（字段名/类型/选项值），缓存 10 分钟；
- 拉取文件写在**系统临时目录**（`lark-cli --output` 只允许「当前工作目录 / 账号临时目录 / home 下的 files」，写别处会被判 `unsafe output path` 退出码 2），用完连 lark-cli 伴生的 `.manifest.json` 一起删。

## 本机接口

都在本工作台自己的前缀下：
`/api/requirement-dev-workbench/{state,settings,sources,requirements,requirement/status,tables,records,fields,overview,view,runs,runs/status,docs,doc,doc/fetch,doc/remove,flows,flows/stage,flows/evidence,flows/evidence/remove,flows/remove,spec-scan,spec-read,skills,skills/create,skill,experts,expert/create,team/create,composer/session,ai/create}`。
其中 `/records`、`/fields`、`/requirements` 都支持 `?table=<表 key>` 指定表。
`/ai/create` 是「页面里直接创建」：工作台调宿主 `llm` 服务拿结构化草稿再自己落盘，不经过对话。`/composer/session` 只存**当前对话的 id**（来自输入框那个「＋ 专家」入口的上报，纯内存、不落盘、不含任何凭证），供「发到对话里做」「送进对话」「发进对话」把内容发进当前对话用。
`/doc/fetch` 走本机 `lark-cli docs +fetch`（只读）拉正文；`/flows` 系列按事件追加写 `flows.jsonl`，只存任务 id、标题、阶段状态与备注，不存飞书凭证。

## 分享给别人用

源码托管在 <https://github.com/chdepanghu/dsh-worker>。别人拿到后有两种装法：

**A. 直接装别人给的安装包（最简单）**

1. 拿到 `dsh-requirement-dev-workbench-<版本>.tgz`；
2. DSH Desktop → **设置 → 插件 → 添加插件**，填这个 tgz 的**完整路径**，安装；
3. 重启 Harness（顶部提示「立即重启」或菜单 **Harness → 重启 Harness**）；
4. 展开左侧栏，在左上角「工作台」切换区选择 **AI Native 工作台**。

**B. 从仓库自己打包**

```bash
git clone https://github.com/chdepanghu/dsh-worker.git
cd dsh-worker
pnpm pack                 # 产出 dsh-requirement-dev-workbench-<版本>.tgz
node test/smoke.mjs       # 可选：跑冒烟测试，默认应该 PASS、无 FAIL
```

然后按 A 的第 2–4 步安装那个 tgz。

**对方需要自己准备的东西**（工作台不含任何人的凭证）：

- 本机装好并登录 `lark-cli`（飞书多维表格/文档的读写都走它，工作台**不保存任何飞书凭证**）；
- 一张自己的飞书需求表（可选开发任务表），以及要开发的项目目录；
- 在工作台「设置」里填项目目录、选表；也可以在项目里放 `.requirement-sources.json` / `.dev-task-sources.json` 让它自动认表。

> 冒烟测试里的真实表信息走环境变量或本机私有文件 `test/smoke.local.json`（已 gitignore，不进仓库）。没有配置时，涉及真实飞书读写的检查会记为 WARN 而不是 FAIL，所以别人 clone 下来也能直接跑。

## 装到本机（这台 DSH Desktop）

按 DSH 工作台包规范打包（`pnpm pack` 产出 `.tgz`，内含声明的服务端/客户端入口与 `cordis.patch.yml`）。在当前这台 DSH Desktop 上，**插件由桌面端自己管理**（包目录是桌面端「插件代次」投影出来的链接），命令行 `dsh plugin add` 只完成一半、不会被桌面端登记，所以请走界面：

1. 打开 **设置 → 插件**（页面写明可填包名、GitHub 仓库地址或**本地目录路径**）；
2. 点 **「添加插件」**，填本仓库打出的 **tgz 完整路径**（本机历次安装都是这样装的，例：`D:\workspace\deepseak_harness\requirement-dev-workbench\dsh-requirement-dev-workbench-4.1.0.tgz`），安装；也可以填本机插件目录的绝对路径（本仓库即 `D:\workspace\deepseak_harness\requirement-dev-workbench`）；
3. 页面提示「该插件已安装，如需升级请卸载后重新安装」时：先去「已安装」卸载旧版本，再重复第 2 步（这样界面名称与版本会一起刷新，不会多出第二个入口）；
4. **完整退出 DSH Desktop 再重新打开**——工作台的界面与后端要重启后才生效；
5. 重开后从左侧入口或「已安装的工作台」进入。

> 业务数据（项目设置、视图配置、执行记录、飞书文档正文、全流程记录）写在 DSH 数据目录的 `requirement-dev-workbench/` 下，**不在插件包里**，卸载重装不会丢。
